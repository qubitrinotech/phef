# KT-3A: итог проверки hard/soft readout

Дата: 2026-09-18 (Europe/Moscow).
Итог по зарегистрированным критериям: **BRIDGE_FAIL**.

## Протокол и основание отчёта

Checkpoint-only оценка двух canonical PHEF checkpoints на одинаковых для hard и soft batch-ах. Обучение и изменение весов не выполнялись.

- Checkpoints: `phef/results/v2sel_k32768_sel262144_s65536_seed7_e6000_best.pt` и `phef/results/v2sel_k32768_sel262144_s65536_seed23_e6000_best.pt`.
- Проверенная загрузка: seed7, epoch 4750; seed23, epoch 5000. Для обоих `sel_acc=0.9999186197916666`.
- Матрица: `(7, 7)`, `(7, 11)`, `(23, 7)`, `(23, 11)`; пара обозначает train seed и eval seed.
- На ячейку: batch size 16 × 64 batch-а = 1024 эпизода; всего 4096.
- Мир: `n_keys=262144`, `n_segments=65536`, `n_values=64`, `overwrite_p=0.3`, `key_dim=32`; модель: `dim=128`.
- Исполнение: dense hard/soft, последовательно на NVIDIA GeForce RTX 4090; без повторных shuffled/masked контролей.
- Спецификация: `experiments/kt3/KT3A_hard_soft_bridge_spec.md`.
- Итоговый артефакт: `artifacts/kt3/kt3a/kt3a_summary.json`.

Отчёт составлен по переданному пользователем выводу загрузки, валидации четырёх ячеек и агрегатора. Исходные JSON с локальной машины не передавались для независимого аудита; `CELL_VALID: PASS` означает прохождение реализованного валидатора, а не доказательство отсутствия всех возможных дефектов.

Tie rate равен 0.000000 в каждой из четырёх ячеек. Использовано зарегистрированное определение: более одной позиции со score не ниже максимума минус `1e-6`.

Итог: **BRIDGE_FAIL**, исключительно из-за превышения допустимого абсолютного hard/soft-разрыва. Порог, знак разрыва и правило verdict после получения результата не меняются.

## Интерпретация и ограничения

- **Hard readout:** обе зарегистрированные проверки точности hard выполнены на этой матрице. Провал bridge не означает низкую точность hard retrieval.
- **Согласованность readout:** требование близости hard и soft не выполнено; soft имеет меньшую агрегированную точность.
- **Причина разрыва:** неизвестна. Для её установления нужны отдельные диагностические измерения; текущие счётчики не локализуют механизм ошибок.
- **Совпадение ошибок:** равенство счётчиков hard retrieval, hard answer и retrieval-value не доказывает совпадения ошибочных эпизодов.
- **Границы:** результат не доказывает превосходства над attention, Transformer, ANN, RAG, Mamba, SSM, RNN или базами данных, не устанавливает capacity frontier и не меняет вывод KT-1.
