# Holographic Hysteresis Memory — ablation report

## Что проверяли

Гипотеза: голографическая память с гистерезисом (персистентное состояние
размерности 1024, инжектируемое в residual stream) даёт трансформеру ёмкость,
недостижимую для обычного causal-декодера того же размера.

Первичное наблюдение, ради которого всё затевалось: на задаче копирования
память показывала ~85% exact-sequence против 1–2% у декодера без памяти.

## Что нашли

Преимущество оказалось артефактом трёх дефектов инфраструктуры.

1. **Неразличимые позиционные коды.** Лоренц-позиционки давали near-duplicate
   пары позиций; точное копирование было физически невозможно, и память
   работала обходным путём. После починки: `min dist 0.3631`,
   `near-duplicate pairs 0` на всех длинах.

2. **Обучение на непредсказуемом префиксе.** Задача — скопировать случайный
   префикс. Сам префикс неучим, но при полном next-token loss он даёт
   78% величины градиента при half=32, 99.6% при half=256 и 99.8% при
   half=512. Полезный сигнал тонул в шуме.

3. **Недостаточный бюджет обучения.** 80–100 эпох обрывали оптимизацию до
   формирования индукционной головы.

## Результаты (param-matched, 8.66M параметров)

С полным loss (архивная серия, `archive_fullloss/`):

| префикс | mem tok | matched tok | mem seq | matched seq |
|--------:|--------:|------------:|--------:|------------:|
|      32 |  99.93% |      99.92% |  97.66% |      97.46% |
|     128 |  99.84% |      99.93% |  80.47% |      91.21% |
|     256 |  34.53% |      98.22% |   0.00% |       0.78% |
|     512 |   3.43% |       5.50% |   0.00% |       0.00% |

С copy-only loss (корректная постановка):

| префикс | эпох | mem tok | matched tok | mem seq | matched seq |
|--------:|-----:|--------:|------------:|--------:|------------:|
|     256 |  200 | 100.00% |      99.99% |  99.61% |      97.27% |
|     512 |  250 | 100.00% |      99.99% |  99.61% |      95.12% |

**Вывод:** гистерезисная память не превосходит param-matched causal-декодер на
копировании при длинах префикса 32–512 токенов. Оба варианта решают задачу
практически идеально. Разрыв 99.61 vs 95.12 на 512 — это разница между «ноль
ошибок» и «одна ошибка на 10 000 токенов», то есть шум одного сида:
0.9999^512 = 95.01%, что совпадает с наблюдаемыми 95.12%.

При шумном градиенте память деградирует ЗАМЕТНО СИЛЬНЕЕ baseline
(34.53% vs 98.22% на префиксе 256) — усреднение префикса подаёт в residual
сжатый шум.

Память также замедляет доведение точности. Разрыв между эпохой достижения
50% token acc и 50% exact-seq: у baseline 0 эпох (11 и 11 на L=65),
у памяти 17 эпох (15 и 32). С чистым loss разрыв выравнивается (30 vs 31),
то есть замедление вызвано взаимодействием памяти с шумной частью градиента.

## Проверки корректности

* Train loss совпадает с информационно-теоретическим floor во всех прогонах
  (расхождение < 0.01) — memorization отсутствует, данные генерируются свежими.
* exact-seq согласуется с предсказанием `token_acc^half` с точностью до
  0.15 pp — ошибки независимы по позициям.
* Noise-контроль показывал train 6.652 при жёстком floor ln(1000) = 6.9078,
  то есть сам контроль протекал: `NoiseStream` не пере-сеял генератор,
  и 200 батчей повторялись каждую эпоху. Исправлено.

## Почему копирование — тупик для этой гипотезы

Копирование решается одной индукционной головой. Обе архитектуры достигают
потолка, и задача теряет разрешающую способность. Нужна задача, где информация
обязана пережить сброс контекста.

## Следующий шаг: segmented key-value recall

`experiments/train_recall.py`. Сегменты пар ключ-значение подаются ОТДЕЛЬНЫМИ
forward-проходами. Attention пересобирается на каждом сегменте, поэтому
декодер без памяти структурно на уровне chance (1/n_values). Единственный
канал, переживающий сброс — персистентное состояние.

Логика вывода:
* baseline у chance + память выше chance -> гистерезис работает;
* оба у chance -> канал памяти не несёт информации;
* baseline выше chance -> задача протекает, результат недействителен.

Три встроенные защиты:
* `--single-context` gate: всё склеено в одно окно, baseline ОБЯЗАН дать >90%,
  иначе сломана задача, а не память;
* shuffled-memory probe: состояние памяти перемешивается между элементами
  батча — точность обязана обвалиться до chance;
* разбивка точности по сегментам: отличает реальную долговременную память
  от «помню только последний сегмент».

Конфигурации: 2x8, 4x8, 8x8, 4x16 пар (от 16 до 64 пар на memory_dim=1024).

```bash
bash experiments/run_recall.sh
```

## Изменения в коде

* `--loss-on-copy-only` стал поведением по умолчанию; legacy доступен через
  `--loss-on-full-sequence` (теги получают суффикс `-fullloss`).
* `NoiseStream.__iter__` пере-сеет генератор каждую эпоху.
* Бюджеты в `run_ablation.sh`: L=257 -> 80 эпох, L=513 -> 200, L=1025 -> 250.
