### 4.12 Отбор чекпойнта в v6 идёт по метрике, потерявшей связь с отчётом — **из вывода терминала**

`hard_soft_gap`: seg 64 s0 +0.4080; seg 256 +0.4799 / +0.4812 / +0.4908. `best_sel_acc` (мягкий пробник, `sel_world`) 0.4453 … 0.6675 при отчётном `answer_acc` 0.8908 … 0.9929. `entropy_norm` вырос с 0.015–0.027 (база) до 0.144–0.193.

То есть при зажатом наклоне мягкий ридаут почти перестаёт работать, отбор идёт фактически вслепую относительно печатаемой метрики — и всё равно выигрывает. Это делает пару `--recency-value` + `--select-metric hard` осмысленным экспериментом, в отличие от вырожденного случая 4.9.

Объяснение (**арифметика агента**, не измерение): внутри слота семантика побитово одинакова (4.5), поэтому при малом наклоне softmax размазывает вес по всем событиям слота и усредняет значения, включая устаревшие; жёсткому аргмаксу микроскопического наклона хватает, чтобы взять последнее.

### 4.13 Побитовой воспроизводимости обучения нет — **из вывода терминала**

Два прогона с идентичными аргументами (`sel_soft` и `sel_soft2`) дают весь stdout побайтно одинаковым, но в `state_dict` расходится **ровно один тензор**: `value_emb.weight`, на `1.192e-07` (один ULP float32). Остальные 15 тензоров совпадают побитово, NaN нет (`self=True`, `nan=0` у всех).

Расхождение `soft` против `hard` **в точности такое же**, как у контрольной пары, — то есть к флагу отношения не имеет.

Вероятная причина — недетерминированное накопление градиента в backward у `nn.Embedding`; **гипотеза, не проверенная**. Практического влияния на печатаемые метрики нет.

### 4.14 `memory_gate` ≈ 16.6356 во всех двенадцати прогонах — объяснено

Значение совпадает до четвёртого знака в v5 и v6, при любой длине, точности и зажиме (16.6355 … 16.6359).

Объяснение (**арифметика агента**, проверяется прогоном с другим `weight_decay`): при таком значении `sigmoid` равна \(1 - 6\cdot10^{-8}\), её производная тоже \(6\cdot10^{-8}\), градиент от лосса через гейт исчез; `AdamW` с `weight_decay=1e-4` тянет параметр вниз с силой \(1.7\cdot10^{-3}\). 16.6356 — точка равновесия между исчезающим градиентом и распадом весов, куда параметр приходит из любой стартовой позиции.

**Содержательной информации это число не несёт.** Гейт открыт полностью, память используется целиком.

### 4.15 Прочее унаследованное

- Гейт «numpy против gpu» при dim 8: грубого расхождения нет, мощность около нуля (p = 0.70).
- Бюджет 30k → 1M при одном мире: 3 из 3 в одну сторону, p = 0.125. Кандидат в гипотезу.
- Закон escape по `v4_clean` цел; escape и бассейн — разные вещи.
- Для dim 8 файлы в `v4` и `v4_clean` дублируются побайтно.

## 9. Чего не делать

- Не сравнивать сиды по номеру между мирами numpy и gpu — генераторы разные.
- Не сравнивать `escape_epoch` между прогонами с разным `acc_every`.
- Не считать файлы `v4` и `v4_clean` для dim 8 как независимые.
- Не читать столбец `answer` в абляции при множителе 0 — он обрушен по построению.
- Не делать выводов о ёмкости по прогонам, где `best_epoch` близок к `epochs`.
- Не запускать длинную серию, не прогнав ту же конфигурацию на малом бюджете.
- Не сравнивать числа из файлов с разным `eval_seed_offset`.
- Не подбирать порог «почти равенства» — он измерен и равен нулю (4.5).
- Не возвращаться к правке `model.py` ради двухступенчатого ридаута без нового довода.
- Не считать приложенную к чату копию `.py` основанием для правки — требовать `cat -n`.
- **Не читать `best_sel_acc` и `best_acc` в v6 как оценку качества** — это мягкий пробник, потерявший связь с отчётом (4.12).
- **Не сравнивать `score_scale` между v5 и v6 как «ту же величину»** — при разном `recency_scale` они масштабируют разное (4.11).
- **Не говорить «совпало побитово» про веса без проверки `state_dict`** — есть 1 ULP в `value_emb.weight` (4.13).
- **Не придавать смысл значению `memory_gate` ≈ 16.6356** — это равновесие градиента и weight decay (4.14).
- **Не ставить `git` в `&&`-цепочку перед серией прогонов**: «nothing to commit» возвращает код 1 и молча съедает весь запуск. Проверено ошибкой в этой сессии.
- **Не запускать, не убедившись в активном venv** — префикс `(venv)` в приглашении (см. раздел 2).
- Не подмешивать новые прогоны в `results/v5/` — по нему сверяется раздел 1 и ходят пробники по `--glob`.
