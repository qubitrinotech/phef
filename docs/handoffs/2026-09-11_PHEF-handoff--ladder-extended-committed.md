## 3. Снятые в этой сессии интерпретации (не воскрешать)

Все три были выдвинуты ассистентом по частичным данным и опровергнуты последующими точками той же лестницы. Записаны именно для того, чтобы не повторять.

1. **«alpha ≈ 0.38 — новый закон, экстраполяция к N ~ 1e10.»** Выдвинуто по трём точкам. **Снято** четвёртой точкой: локальный наклон подскочил до 0.771.
2. **«Наклон 1.164 на пятой точке — начало насыщения, кривая ускоряется.»** **Снято** шестой точкой: наклон вернулся к 0.692. Последовательность 0.379 / 0.387 / 0.771 / 1.164 / 0.692 не монотонна. При 2048 эпизодах и ошибке ~0.03 сигма ≈ 0.0039, что даёт неопределённость локального наклона порядка ±0.2.
3. **«Точка 50% ошибки около 2–5e7 при alpha ≈ 0.51.»** Промежуточная оценка, заменена на 2–4e7 при alpha = 0.876 (§2.3). Численно близко, но обоснование другое.

**Методологический урок:** локальные наклоны по двум соседним точкам при 2048 эпизодах шумны до ±0.2. Интерпретировать только подгонку по ≥4 точкам; не объявлять смену режима по одному удвоению.

## 4. Унаследованные факты (контекст, не переизмерялось)

### 4.1 Ось n_keys при инференсе мертва

**[FACT]** Модель PHEF поточечна по оси ключей. В `phef/model.py`: `memory_keys = key_encoder(codebook)`, затем `semantic = gather(einsum("bd,bkd->bk", query_state, memory_keys) / sqrt(dim), 1, slots)`. Редукции по оси `k` нет. `EventMemory` в `phef/memory.py` — мёртвый код. Ветка «эвал на 8M ключей» снята: измеряла бы изменение сложности 0.29% при шуме 0.11%.

### 4.2 key_dim = 64 хуже key_dim = 32

**[FACT]** Та же лестница, конфиги идентичны кроме `key_dim`:

| N_eff | ошибка kd32 | ошибка kd64 | отношение |
|---:|---:|---:|---:|
| 45 875 | 0.020020 | 0.183105 | 9.1× |
| 91 746 | 0.037598 | 0.267090 | 7.1× |
| 183 486 | 0.062500 | 0.342285 | 5.5× |
| 366 941 | 0.101074 | 0.411621 | 4.1× |

Показатель kd64 = 0.390. **[FACT]** Численно близок к 0.379–0.387 у `ntrain4096` на нижнем участке, но стартует с ошибки 0.183 против 0.0049 — в 37 раз выше. Пологость без низкого старта ничего не стоит.

**[FACT]** Выученные скаляры kd64 благоприятнее, а не мягче: `score_scale` 2.322308 против 2.014736; alpha/|beta| 1.731073 против 1.481409. **[INFERENCE]** Деградация в геометрии энкодера, не в весах score.

### 4.3 Метрика отбора слепа — подтверждено кодом

**[FACT]** `phef/experiments/train_recall.py`:
- строки 257–267: `train_world`, `eval_world`, `sel_world` строятся из одного словаря `common` → `sel_acc` меряется при том же `n_keys`, что и обучение;
- строка 416: `if probe > best_acc` — строгое сравнение, первое касание 1.0 фиксирует `best_epoch` навсегда;
- `acc_n = 512` в рецепте early → разрешение ≈ 0.002, при `sel_acc = 1.0` не различает модели вовсе.

**[FACT]** kd32 и kd64 обе держат плато `sel_acc = 1.0` с эпохи 4500 до 6000, различаясь по реальной точности в 8 раз. Этот диагноз — прямое обоснование пункта 3 в §7.

### 4.4 Опровергнутые ранее гипотезы

1. «`key_dim` — рычаг ёмкости, kd64 должен быть лучше.» Опровергнуто (§4.2).
2. «kd64 выучил более плоскую маржу из-за лёгкой задачи.» Опровергнуто: `score_scale` и alpha/|beta| у kd64 выше.
3. «kd64 недообучен.» Не подтверждается тренировочной метрикой, но метрика насыщена и слепа. Считать **[UNKNOWN]**.
4. «Оптимум `key_dim` смещается вниз с ростом N_train» (по `_scratch`). **Снята**: `_scratch`-прогоны принадлежат более раннему поколению кода (нет `hard_eval`, `aux_value_weight`, `use_best`, `memory_gate`) и не переносятся.
5. Прогоны `capacity_scan_dim128_keydim64/*` — **не** свидетельство против kd64: шли при `batch_size=64`, системный конфаунд по размеру батча.

## 7. Подводные камни (соблюдать)

- **`eval_batch_size = 1` недопустим:** `PHEF.forward(shuffle=True)` вызывает `torch.randint(1, batch_size, ())`. Минимум 2.
- **Три схемы JSON:** старый эвалюатор кладёт условия на верхний уровень (`real`/`shuffled`/`masked`); MFR — под `results.real`; compact — `schema: "compact_eval_v1"`. Не смешивать.
- **Не патчить `phef/experiments/eval_recall_checkpoint.py`** — это валидированный эталон.
- **Не патчить `phef/experiments/train_recall.py` на месте** — он породил все существующие чекпоинты.
- **`phef/world_gpu.py` непригоден:** `BranchingWorldGPU.__init__` бросает исключение при `n_keys > 32767` (передача слотов в int16). **Прямо блокирует N_train = 32768.**
- **`train_recall.py` печатает без `flush`** (строки 434, 480). При перенаправлении в файл лог пуст первые ~10 минут. Наблюдать прогресс по mtime файла `--best-out`.
- **Пользователь иногда запускает свипы между сообщениями** — всегда переинвентаризировать артефакты.
- Критерии PASS: `hard_eval=true`, `real.answer_acc ≥ 0.90`, `real.retrieval_acc ≥ 0.90`, `shuffled.answer_acc < 0.03125`, `masked.answer_acc < 0.03125`.
- **Локальные наклоны при 2048 эпизодах шумны до ±0.2.** См. §3.
