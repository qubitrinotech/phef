[ФАКТ] В `experiments/analyze_memory.py` сделано:

1. Добавлен CLI-флаг:
   ```python
   --accum-steps
   ```
   с `default=1`.
2. На epoch вызывается один `optimizer.zero_grad(set_to_none=True)`.
3. Выполняется `accum = max(1, args.accum_steps)` микробатчей.
4. Первый микробатч использует уже подготовленный перед циклом `train_world.batch(args.batch_size)`.
5. Микробатчи `micro > 0` запрашиваются заново через `move(train_world.batch(args.batch_size), device)`.
6. Каждый micro-loss — `F.cross_entropy(logits, answers) / accum`.
7. `loss.backward()` вызывается для каждого микробатча; clipping и `optimizer.step()` — один раз после цикла.
8. Для лога используется `current = loss_sum / accum`.

[ФАКТ] Smoke-тест был выполнен и прошёл штатно:

```text
n_segments=32768
batch_size=128
accum_steps=2
epochs=1
init_weights=16384 curriculum checkpoint
```

[ФАКТ] Smoke-артефакты находятся в `results/smoke_accum/` и `logs/smoke_accum/`; они untracked.

[ОГОВОРКА] Накопление не обязано побитово совпадать с прогоном без накопления: при `accum_steps > 1` за epoch вызывается `train_world.batch(...)` несколько раз. Проверка должна быть по заданным метрикам, не по побитовому совпадению.

## 8. Открытые исследовательские вопросы

[НЕИЗВЕСТНО] Почему jump 8192 → 32768 дал `recency_scale=70.48` при `answer_acc=1.0`, тогда как эталон через 16384 дал 99.15. У эталонного старого прогона нет history-trajectory, поэтому объяснять причину нельзя.

[ФАКТ] Gradient accumulation-control по основному маршруту 16384 → 32768 дал `recency_scale=102.35`, близко к эталону 99.15; это сняло технический confound batch size для следующего шага.

[НЕИЗВЕСТНО] Будут ли основные 131072 финальные метрики удовлетворительными за 40000 epochs и куда попадёт `best_epoch`. Не делать выводов по 250-epoch probe.

[НЕИЗВЕСТНО] Длительность и peak-memory полного 131072 ×4. Не использовать предположения. Замерять по реальному логу/nvidia-smi.

[ВЫВОД] После завершения 131072 следующий масштаб 262144 потребует отдельной технической проверки. Нельзя переносить memory/speed автоматически; сначала подобрать/измерить микробатч и eval batch.

4. Не запускать ничего без явного подтверждения пользователя.
5. Для полного 131072 использовать только команду из §6 после свежей проверки весов/GPU и подтверждения.
6. Сравнивать финальные результаты только по корневым полям финального JSON; не подменять их `history[-1]`.
7. Перед коммитом всегда показать `git diff --check`, `git diff --stat`, точный diff и явно исключить чужие/untracked-файлы.
