### 3.2 Фактический код `_sample_slots` (GPU)

[ФАКТ] `phef/world_gpu.py`, строки 67–81:
```python
def _sample_slots(self, bs):
    s = self.n_segments
    slots = self._randint(self.n_keys, (bs, s))

    reuse = self._rand(bs, s) < self.overwrite_p
    reuse[:, 0] = False

    back = self._rand(bs, s)

    for ts in range(1, s):
        source = (back[:, ts] * ts).long().clamp_(0, ts - 1)
        candidate = slots.gather(1, source.unsqueeze(1)).squeeze(1)

    return slots
```

### 3.6 Семантика цикла: истинная зависимость по данным

[ФАКТ] `slots.gather(1, source)` читает `slots[:, source]` при `source < ts`; на итерации `ts` пишется `slots[:, ts]`. Прочитанная позиция могла быть записана на предыдущей итерации.

[ВЫВОД] Это цепочка reuse-переходов: слот может ссылаться на слот, сам переписанный ранее. Наивная векторизация по `ts` **изменит семантику**. Требуется pointer-jumping (log s шагов) либо один CUDA-kernel.

[ФАКТ] Docstring `world_gpu.py` строки 10–13: «slots: случайные, с вероятностью overwrite_p переписывающие случайный ПРЕДЫДУЩИЙ слот (**цикл по сегментам последователен**)».
[ВЫВОД] Последовательность зафиксирована как контракт совместимости с `world.py`, не деталь реализации.

[ФАКТ] Docstring строка 21: «Побитовой RNG-совместимости с numpy-версией нет и быть не может. Совместимость проверяется распределённо: `experiments/parity_check.py`».
[ВЫВОД] Побитовая совместимость не требуется изначально — достаточно распределённого совпадения. Это открывает дорогу любой замене цикла, прошедшей parity.

### 4.1 CPU numpy-цикл

[ФАКТ] `phef/world.py`, строки 32–56, тело `_sample_slots`:
```python
slots = self.rng.integers(0, self.n_keys, size=(bs, self.n_segments))
reuse = self.rng.random((bs, self.n_segments)) < self.overwrite_p
reuse[:, 0] = False
back = self.rng.random((bs, self.n_segments))
rows = np.arange(bs)
for ts in range(1, self.n_segments):
    source = (back[:, ts] * ts).astype(np.int64)
    source = np.clip(source, 0, ts - 1)

```

[ВЫВОД] Структурно идентичен GPU-версии. `slots[rows, source]` — fancy indexing, прямой эквивалент `gather`.
